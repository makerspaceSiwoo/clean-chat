# OPEN-03 OCR 비교 기록

2026-11-28 (Asia/Seoul). 기본 엔진 변경 전 후보 평가이며 실제 게임 성능 확정 자료가 아니다. 이후 사용자 요청으로 RapidOCR을 기본 엔진으로 전환했다(ADR-0023). 아래 결과와 당시 평가 결론은 그대로 보존한다.

## 데이터와 방법

- 사용자 제공 `synth_v1.zip`: Figma로 만든 합성 이미지 138장과 정답. 실제 롤 캡처가 아니며 닉네임은 가상 이름이다. 원본 ZIP은 수정하지 않았다.
- 각 A/B/C 스트립에서 `000, 008, 016, 024, 032, 040`의 6장씩 총 18장. 500×300 이미지의 창 이동 간격이 150px이므로 선택 창 간에는 픽셀 중복이 없다. 인접 프레임 50% 중복으로 평가가 부풀려지는 것을 피했다.
- 정답의 `visible=full` 줄만 포함하도록 공통 세로 영역을 먼저 자른다. 같은 영역을 세 엔진에 입력한다. 정확도 평가는 물리적 화면 줄 기준이며 채팅 줄 병합·허용 문자 치환·반복 자모 보정은 적용하지 않는다.
- CER = 총 Levenshtein 편집 거리 / 총 정답 문자 수(7,501자). NFC와 연속 공백만 정규화한다. 문장부호·대소문자·호환 자모를 유지한다. 줄바꿈은 공백으로 취급한다.
- 자모 표현 = `[ㄱ-ㅣ]+`의 최대 연속 구간. 편집 거리 정렬에서 같은 위치에 글자 수까지 완전히 일치할 때 성공이다. 잘못된 반복 개수를 성공으로 세지 않는다.
- 자모 욕설 지표는 위 구간 중 `ㅅㅂ`, `ㅆㅂ`, `ㅂㅅ`, `ㅈㄴ`, `ㅗ+`와 완전히 일치하는 구간을 대상으로 한다. 이번 선택 표본에는 `ㅂㅅ` 1건과 `ㅗ+` 8건만 있다. 문맥에 따른 유해성 판정이나 모든 욕설을 포괄하는 지표가 아니다.
- 엔진당 1회 워밍업 후 이미지당 3회, 총 54회 측정. 파일 로딩·공통 자르기는 제외하고 RGB/BGR 변환·2배 확대·검출·인식·행 합치기를 포함한다. Windows 2배 확대는 LANCZOS. 반복 출력은 모두 동일했다.
- 환경: Windows 10.0.26200, Intel64 Family 6 Model 186 Stepping 2, Python 3.11. CPU ONNX Runtime(내부 스레드 4, 외부 스레드 1). GPU 미사용. 설치 버전 `rapidocr=3.10.0`, `onnxruntime=1.32.0`. 다른 OS/CPU에서의 속도는 미검증.
- 다른 작업과 자원 경합이 있을 수 있는 로컬 측정이므로 짧은 시간 차이를 엄밀한 성능 우열로 해석하지 않는다. 약 3배 차이는 최적화 검토 근거이며 실시간 목표 충족을 뜻하지 않는다.
- macOS 설치용 ONNX Runtime은 `>=1.20,<1.24`로 분리했다. [1.23.2 배포 파일](https://pypi.org/project/onnxruntime/1.23.2/#files)은 macOS 13 이상 arm64/x86_64 휠을 제공한다. `uv pip compile --only-binary :all:`로 Python 3.11의 두 Mac 아키텍처 의존성 해석을 확인했다. macOS 설치/추론 실측 결과로 해석하지 않는다.

RapidOCR은 일반 문자 오류가 적지만, 자모 욕설과 프레임당 0.5초 목표를 충족하지 못한다. Windows 원본은 빠르지만 정확도와 자모 욕설에서 우세하지 않다. 2배 확대는 이 데이터에서 개선되지 않았다. 따라서 Windows 유지나 RapidOCR 단독 전환을 확정하지 않는다. 기존 EasyOCR은 이번 비교 대상에 없으므로 우수하다는 결론도 내리지 않는다.

실제 롤 캡처 10~20장(실제 닉네임 제거), 다양한 색·배경·글자 크기와 `ㅅㅂ`, `ㅂㅅ`, `ㅗ`, 반복 자모를 포함한 정답으로 재평가한다. 추가 합성 데이터나 모델 튜닝 결과는 이번 고정 표본 결과와 분리해서 기록한다.

## 사전과 가중치 확인

- [공식 한국어 사전](https://raw.githubusercontent.com/PaddlePaddle/PaddleOCR/main/ppocr/utils/dict/ppocrv5_korean_dict.txt)과 [RapidOCR 배포 사전](https://www.modelscope.cn/models/RapidAI/RapidOCR/resolve/v3.10.0/paddle/PP-OCRv5/rec/korean_PP-OCRv5_rec_mobile/ppocrv5_korean_dict.txt)을 각각 내려받아 검사했다. 두 파일의 11,945개 항목과 SHA-256이 동일하다.
- 사전 SHA-256: `a88071c68c01707489baa79ebe0405b7beb5cca229f4fc94cc3ef992328802d7`.
- `ㅋ` U+314B: 265번째 줄, `ㅗ` U+3157: 277번째 줄, `ㅅ` U+3145: 259번째 줄, `ㅂ` U+3142: 256번째 줄. `ㅎ`, `ㄱ`, `ㅠ`, `ㅜ`도 포함한다. 포함 여부는 출력 가능성을 뜻하며 학습·정확도를 보장하지 않는다.
- 실제 ONNX 인식 모델의 `character` 메타데이터도 11,945개 항목이며 위 4개 문자가 포함돼 있다. ONNX 엔진은 이 내장 목록을 사용하므로 별도 사전만 임의로 바꿔 끼우지 않는다.
- 검출 모델 SHA-256: `4d97c44a20d30a81aad087d6a396b08f786c4635742afc391f6621f5c6ae78ae`.
- 인식 모델 SHA-256: `cd6e2ea50f6943ca7271eb8c56a877a5a90720b7047fe9c41a2e541a25773c9b`.
- 정답 파일 SHA-256: `0917642219e9151afc065daffc0f0ba90ab627a00e9f30bbcbe5ced6af92618f`.
- 모델은 SDK가 최초 추론 시 다운로드하고 해시를 검증해 `.clean-chat/rapidocr/`에 저장한다. 가중치·원본 이미지·원문별 측정 결과를 커밋하지 않는다. `.gitignore`의 `.clean-chat/`, `*.onnx` 규칙을 따른다.

## 재현

승인받은 의존성을 설치한 뒤 ZIP의 `synth_v1/images/`, `labels.jsonl`을 `.clean-chat/ocr-benchmark/synth_v1/`에 둔다. ZIP 안의 도구 스크립트를 실행할 필요는 없다.

```bash
uv sync --extra ocr
uv run --extra ocr python -m clean_chat.modules.ocr.benchmark .clean-chat/ocr-benchmark/synth_v1
```

기본 보고서는 `.clean-chat/ocr-benchmark/results.json`이다. 정답·인식 결과·프레임별 시간·이미지 해시·패키지 버전이 포함된다. Mac에서는 Windows 비교 두 항목을 `unavailable`로 표시하고 RapidOCR만 측정한다. 로딩과 첫 추론 시간도 별도로 기록하지만 다운로드 캐시 상태가 다를 수 있어 순수한 콜드 스타트 비교로 쓰지 않는다.
