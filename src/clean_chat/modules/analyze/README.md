# ③ analyze — 분석 — 대상·등급·피드백

명세: `docs/MODULES.md`의 `analyze` 절 · 계약: `docs/CONTRACTS.md` · 예시: `fixtures/analyze/`

**할 일은 `impl.py` 의 `run(AnalyzeRequest) -> Analysis` 함수 하나입니다.** docstring 의 예시·순서·주의를 따라 본문을 채우세요.

| 파일 | 내용 | 수정 |
|---|---|---|
| `impl.py` | `run()` + 제안용 도우미 함수 (`_`로 시작, 바꿔도 됨) | ✅ |
| 그 밖의 파일 | 이 폴더 안에 자유롭게 추가 (사전, 프롬프트, 내부 모듈) | ✅ |
| `fixtures/analyze/input.jsonl` | 입력 예시 추가 | ✅ |
| `fixtures/analyze/expected.jsonl` | 기대값 (명세) | 리드 승인 |
| `tests/test_analyze.py` | 내 테스트 추가 | ✅ |

- **구현 방식: 로컬 소형 분류 모델 + 규칙** (LLM·외부 API 아님). 모든 채팅에 실행되므로 CPU 1문장 0.2초 이내가 목표입니다. 가중치는 `models/`(git 제외), 무거운 로딩은 `functools.cache` 로 한 번만.
- AI 모듈: 출력 형식만 자동 검사하고, 정확도는 `training/` 평가와 `data/eval/` 로 봅니다.
- **대상(target)은 닉네임입니다 (ADR-0020).** 채팅은 `닉네임 (챔피언)` 뿐이라 "정글"이 누구인지는 챔피언의 주 라인과 앞 대화로 추정합니다. 한 명으로 못 좁히면 포지션 단어를 그대로 둡니다.
- 숨김·신고 같은 처리는 하지 않습니다. 정책표(`core/policy.py`)가 이 결과를 보고 정합니다. 라벨 기준: `docs/LABELING_GUIDE.md`.
- 브랜치는 `analyze/<작업 내용>` 으로 만듭니다(예: `analyze/first-try`). PR 에서 위 표의 범위 밖 파일을 바꾸면 CI `module-scope` 가 실패합니다(CONTRIBUTING.md).
- 다른 모듈 폴더는 import 하지 않습니다. 함수 이름 `run` 과 입출력 타입은 바꾸지 않습니다(바꿔야 하면 "계약 변경 요청" 이슈).

## 폴더 구성 — 용도 2개

두 용도는 **과제가 다르다.** 데이터·모델·평가 도구·속도 기준을 따로 둔다.

| 용도 | 언제 | 파일 | 하는 일 | 속도 기준 |
|---|---|---|---|---|
| **실시간 필터 (impl)** | 게임 중, 메시지마다 | `impl.py` `run()` | 문장 1개 → 숨길 욕설 조각, 비난·패드립·성희롱·정치질 여부, 피드백 조각 (원본과 숨김 문장을 보여 주기 위한 값) | 0.5초 미만 (최대 1초 미만) |
| **대화 판단 (judge)** | 게임 종료 후, 한 판에 1번 | `judge.py` `judge()` · `judge_session()` | 한 판(최대 10명)의 채팅을 **유저별로 모아** 누적 점수와 흐름으로 신고 권고 · 고소 후보 | 1~5초 (5초 이상이면 로딩 창) |
| └ 판례 대조 | 대화 판단의 마지막 단계 | `precedents.py` `review()` | 고소 후보에 죄목별 요건 점검표(충족/불명/미충족) + 비슷한 판례 |

- 신고·고소처럼 무거운 결정은 한 문장이 아니라 **대화 흐름**(반복, "ㅇㅈ" 같은 동조, 여러 명의 몰이)으로 판단합니다.
- impl 쪽 파일: `lexicon.py`(사전), `champions.py`(챔피언 → 주 라인·줄임말), `model.py`(impl 모델 연결), `train.py`(학습), `public_data.py`(공개 데이터 → 학습 CSV), `evaluate.py`(impl 평가).
- judge 쪽 파일: `judge.py`(누적 점수·흐름 규칙), `judge_model.py`(judge 전용 모델: 입력 문서·학습·추론), `judge_evaluate.py`(게임 단위 평가), `precedents.py`(판례 대조).
- 노트북(`notebooks/`): `demo_impl.ipynb` · `demo_judge.ipynb` — 각 과제의 데이터, 파인튜닝, 정답률·오답률, 응답 시간을 실행 결과와 함께 본다. `model_demo.ipynb` 는 인코더·분류 층·벡터 유사도 설명.

### 파인튜닝 모델 넣기
`models/analyze-classifier/`(git 제외)에 모델이 있으면 `run()` 이 자동으로 씁니다. 없으면 규칙만으로 돕니다.
```bash
uv sync --extra analyze
uv run python -m clean_chat.modules.analyze.train \
    --data fixtures/analyze/labeled_parsed.csv fixtures/analyze/train_aug.csv \
    --base beomi/KcELECTRA-base --version kcelectra-base-ft-0.2 --epochs 20 --patience 6 --lr 5e-5 --seed 1
uv run python -m clean_chat.modules.analyze.evaluate fixtures/analyze/labeled_parsed.csv --split test   # 브랜치·모델끼리 같은 명령으로 비교
CLEAN_CHAT_ANALYZE_MODEL=<다른 모델 폴더> uv run python -m clean_chat.modules.analyze.evaluate fixtures/analyze/labeled_parsed.csv --split test
```
- 모델은 유형 점수만 냅니다. 규칙 점수와 유형별로 큰 값을 쓰고(기준 0.5), 등급·대상·조각은 규칙이 정합니다.
- **욕설(profanity)은 모델 점수를 쓰지 않고 규칙만 씁니다**(`impl.py` `_RULE_ONLY`). 사전이 이미 정확하고, 모델만 걸린 욕설은 가릴 조각이 없으며, 정상 문장 오탐이 여기서 나왔기 때문입니다(아래 비교 참고).
- 라벨 CSV 열: `text`, `text_norm`, `hints`, `level`, `harm_types`, `profanity_spans`, `split`(`train`/`test`). `test` 행은 학습에 쓰지 않습니다.
- `train.py` 는 train 행의 15%를 검증용으로 떼어 가장 좋은 epoch 의 가중치를 저장하고(조기 종료), 드문 유형은 양성 가중치로 보정합니다. 결과는 `meta.json` 에 남습니다.
- `Analysis.model_version` 은 `rule-0.2+<모델 버전>` 으로 남습니다.

공통 계약에 유해 유형 **`threat`(협박)** 이 추가됐다(ADR-0021). analyze 의 판정 기준과 결과는 아래와 같다.

#### 협박 기준 — 정밀도 우선, 애매한 것은 흐름에서
협박 = **게임 밖 현실의 해악**을 **상대에게 가하겠다**고 알리는 말. L3 는 내 채팅 차단·고소 후보로 이어지므로 잘못 잡는 것이 놓치는 것보다 해롭다. 그래서 문장 하나로 정하는 impl 은 확실한 것만 잡고, 애매한 것은 대화 흐름을 보는 judge 가 정한다.

| 단계 | 무엇 | 예 | 누가 판정 |
|---|---|---|---|
| ① 명시적 협박 | 현실 표지가 문장에 있다: 주소·사는 곳·신상·현피·"현실에서 만나"·신체 부위를 부러뜨린다 | 너 집 주소 안다 찾아간다 / 신상 털어서 올린다 | impl 규칙(`lexicon.THREAT`) → 문장만으로 `threat` · L3 |
| ② 모델이 본 협박 | 규칙에는 없지만 모델 점수가 0.5 이상이고 **게임 표지가 없다** | 니 인스타 찾았다 다 뿌려줄게 / 계정 해킹해서 날려버린다 | impl 모델. 게임 표지(`lexicon.GAME_TALK`: 상대·한타·용·궁·"죽이자"·"잡자" …)가 있으면 받지 않는다 |
| ③ 암시적 협박 | 문장만으로는 알 수 없다 | 끝나고 보자 / 각오해라 / 닉 기억해둔다 / 끝까지 따라다닌다 | impl 은 협박으로 보지 않는다. judge 가 **그 사람을 공격하던 유저가 15분 안에 이어서 했을 때만** `threat` · L3 로 올린다(`lexicon.THREAT_VEILED`) |

협박이 아닌 것:
- **게임 안의 행동**: 바론 죽인다 가자 / 상대 원딜 찾아가서 죽이자 / 제드 보이면 물어서 죽여 / 다음 한타 때 너부터 잡는다
- **게임 안의 보복 예고**: 다음 판에 만나면 니 라인만 판다 / 또 만나면 닷지한다 → 비난(L2)
- **정당한 대응**: 채팅 다 캡처해 둔다 / 차단한다 / 끝나고 신고한다 → 정상(몰이면 정치질)
- **과장·감탄**: 아 죽겠다 ㅋㅋ / 이번 판 지면 죽는다 나 승급전임

이렇게 정한 이유(실험): 협박 시험 40문장에서 **규칙만으로는 협박의 20%만 잡고**, **모델만 믿으면 학습할 때마다 정상 문장 오탐이 5~32%로 갈렸다**(게임 콜 "다음 용 때 다 죽인다 모여" 를 협박으로 봄). 게임 표지로 모델 점수를 막자 다섯 번 학습한 모델 모두 협박 정밀도 100%, 정상 오탐 0~5.3% 로 모였다.

|---|---|---|---|---|

- 남은 오답(협박 시험): "너네 학교 앞에서 기다릴게 나와라", "너 내일 학교에서 보자 각오하고 와" 를 놓치고(해악을 직접 말하지 않는 협박), "방금 한타 사진 찍어서 올려야겠다 ㅋㅋ" 를 L3 로 본다.
- **데이터**: 유형이 비어 있던 협박 8행에 `threat` 를 달고, 협박 30행 · 협박처럼 보이는 게임 안의 정상 문장 30행 · 경계 사례 5행 · 정당한 대응 18행을 더했다(`train_aug.csv` note `보강4`, 학습 문장 총 1,126행). 첫 학습분이 "채팅 다 찍어둔다"·"둘 다 차단한다" 를 협박으로 봐서 정당한 대응 문장을 추가했다.
- **대상 추정 수정**: 탑이 한 말 "세주 너 일부러 탑 안 오지" 에서 대상을 라인 이름 "탑" 으로 잡던 것을, **이름으로 부른 사람(세주아니)** 이 먼저가 되게 고쳤다. 이 때문에 judge 가 나를 향한 협박을 놓치고 있었다.
- **judge**: impl 의 `threat` 판정을 쓰고, 대상 없는 협박은 앞서 공격하던 사람에게 한 말로 본다. 고소 후보의 요건 점검에 **협박(형법 제283조)** 항목이 따로 붙는다(해악의 고지 · 상대방에게 도달 · 공포심을 일으킬 정도). 점검표는 초안이고 법률가 검토가 필요하다.
- **주의**: 협박 시험 40문장도 AI 가 썼고, 게임 표지 목록과 대상 추정은 이 시험셋과 judge 게임의 오답을 보면서 고쳤다. 실제 채팅에서의 수치가 아니다. 게임 표지 목록은 사람이 유지해야 하는 사전이라 새 게임 용어가 빠지면 ② 에서 오탐이 날 수 있다.
- **report 담당자에게**: `Analysis.harm_types` 에 `threat` 가 들어온다(등급 L3). 고소장 초안에서 모욕·통신매체이용음란과 별도 죄목(형법 제283조)으로 다루면 된다. 신고 문구에서는 "협박"으로 표시. 암시적 협박(③)은 실시간 결과에는 없고 judge 결과에만 있다.

| 방식 (시험 18판 · 유저 162명) | 신고 권고: 정밀도 / 재현율 | 고소 후보: 정밀도 / 재현율 | 1판 평균 |
|---|---|---|---|
| 규칙 `judge-0.1` (이전) | 64.5% / 90.9% (A 묶음 18판 기준) | 100% / 50.0% (A 묶음) | 약 0.4초 |
| **규칙 `judge-0.2` (기본)** | **94.4% / 85.0%** | **100% / 83.3%** | 0.40초 |
| 전용 모델만 (`demo_judge.ipynb` 실행분) | 90.9% / 100% | 50.0% / 16.7% | 0.90초 |
| 규칙 + 전용 모델 (같은 실행분) | 87.0% / 100% | 83.3% / 83.3% | 0.89초 |

- **전용 모델은 지금 쓰지 않는다.** 학습 문서가 169개(고소 후보 양성 8개)뿐이라 학습이 불안정했다: 원래 KcELECTRA-base 에서 출발하면 배우지 못했고(15·30 epoch), impl 모델에서 출발해도 학습률 5e-5 는 실패, 3e-5 만 배웠다(검증 F1 0.79, 검증 문서 29개). 배운 모델도 믿고 쓸 수준이 아니다. 같은 설정을 세 번 돌린 결과가 모두 달랐다(전용 모델만: 신고 93.3% / 70.0% · 76.9% / 100% · 90.9% / 100%, 고소 0% / 0% · 42.9% / 50.0% · 50.0% / 16.7%). 신고 권고는 규칙이 놓치는 유저를 잡아 주는 실행도 있지만(재현율 100%), 고소 후보는 매번 나빴다. 규칙이 못 잡는 것(욕설 없는 비꼼의 반복, 킬뎃만 던지는 조롱)이 모델의 몫이므로 게임 데이터가 늘면 다시 비교한다.
- **주의:** 협박 감지와 이어받기 규칙은 시험 게임의 오답을 본 뒤 넣었다. 그 전의 `judge-0.2` 시험 수치는 신고 94.1% / 80.0%, 고소 100% / 33.3% 였다. 고소 후보 정답은 시험에 6명뿐이라 1명이 17%p 다.
- 고소 후보는 **후보**일 뿐이고 법률 자문이 아니다. judge 는 아직 앱 흐름에 연결되어 있지 않다(아래 "다음 단계").

### 다음 단계 (계약 변경 필요 → 리드, ADR)
- 대화 판단은 아직 앱 흐름에 연결되지 않았습니다. 지금은 정책표가 실시간으로 신고·고소 후보를 표시합니다. 연결하려면 모듈 추가(`core/modules.py`·`core/schemas.py`), 게임 종료 배치가 `judge` 를 부르고 그 결과를 report 로 넘기는 변경이 필요합니다.
