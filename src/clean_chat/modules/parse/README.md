# ② parse — 채팅 추출 — 시스템 메시지 제외 + 정규화

명세: `docs/MODULES.md`의 `parse` 절 · 계약: `docs/CONTRACTS.md` · 예시: `fixtures/parse/`

**할 일은 `impl.py` 의 `run(ParseRequest) -> ParseResult` 함수 하나입니다.** docstring 의 예시·순서·주의를 따라 본문을 채우세요.

| 파일 | 내용 | 수정 |
|---|---|---|
| `impl.py` | `run()` + 제안용 도우미 함수 (`_`로 시작, 바꿔도 됨) | ✅ |
| 그 밖의 파일 | 이 폴더 안에 자유롭게 추가 (사전, 프롬프트, 내부 모듈) | ✅ |
| `fixtures/parse/input.jsonl` | 입력 예시 추가 | ✅ |
| `fixtures/parse/expected.jsonl` | 기대값 (명세) | 리드 승인 |
| `tests/test_parse.py` | 내 테스트 추가 | ✅ |

- 규칙 모듈: fixtures 기대값과 **정확히 같아야** 합니다(현재 예시 10건).
- 우회어 사전은 `data/lexicon/` 에 둡니다. 내 입력(흐름 B)도 `source=self_input` 줄로 이 함수를 거칩니다.
- 브랜치는 `parse/<작업 내용>` 으로 만듭니다(예: `parse/first-try`). PR 에서 위 표의 범위 밖 파일을 바꾸면 CI `module-scope` 가 실패합니다(CONTRIBUTING.md).
- 다른 모듈 폴더는 import 하지 않습니다. 함수 이름 `run` 과 입출력 타입은 바꾸지 않습니다(바꿔야 하면 "계약 변경 요청" 이슈).

```bash
uv run sim parse                         # 브라우저: 입력 | 디버깅 콘솔(print·logging·오류) | 반환값
uv run pytest tests/test_parse.py        # 자동 테스트 (구현 전이면 skip)
uv run python scripts/pack_context.py parse   # 웹 AI 채팅에 첨부할 맥락 묶음
```
모듈 코드를 고친 뒤 시뮬레이터에서 [실행]만 다시 누르면 됩니다(서버를 다시 켤 필요 없음).

## 마일스톤 2: OCR 헤더 대응

`source=ocr`와 `demo`의 줄에서 채널·화자·챔피언·본문을 분리합니다. 지원하는 헤더 구분자는 다음과 같습니다.

| 요소 | 허용 형식 | 예시 |
|---|---|---|
| 채널 | `팀`, `전체`. 대괄호·소괄호·전각 괄호와 괄호 안 가로 공백 | `[팀]`, `(팀)`, `[팀)`, `［ 팀 ］`, `（전체）` |
| 화자 | 공백이 있는 닉네임 허용. 헤더 구분자와 괄호가 닉네임에 섞이면 제외 | `불꽃 남자` |
| 챔피언 | 생략 가능. 소괄호·전각 소괄호 허용. 빈 괄호는 제외 | `(징크스)`, `（징크스）` |
| 본문 구분자 | 콜론·세미콜론과 각각의 전각 문자 | `:`, `;`, `：`, `；` |

- 채널을 읽지 못했지만 나머지 헤더가 정상이라면 `channel=unknown`입니다. 채널·화자·챔피언 문자를 추측해서 채우지 않습니다.
- 닫는 채널 괄호가 없거나 챔피언 괄호가 끊긴 줄은 잘못된 화자를 만들지 않고 `message=None`으로 돌려줍니다. 줄 합치기는 OCR 모듈의 책임입니다.
- `raw`는 원본 전체입니다. `text`는 본문 구분자와 직후의 공백 또는 탭 하나를 제외한 본문이며, 내부 기호·공백·후행 공백을 보존합니다. 헤더의 OCR 구분자 대응을 본문에 적용하지 않습니다.
- `source=self_input`은 헤더·시스템 판별을 거치지 않습니다. `/all` 명령 외에는 사용자가 쓴 문장을 본문으로 사용합니다.

## 시스템·UI 줄을 제외하는 기준

채널 표기가 없는 줄에서 아래 전체 형식을 검사합니다. 본문에 특정 단어가 있다는 이유만으로 채팅을 버리지 않습니다.

- `초코우유 (리신)님이 … 신호를 보냈습니다`, `초코우유님이 … 처치했습니다`
- `초코우유님이 게임을 종료했습니다`, `초코우유님이 게임을 떠났습니다`
- 위 알림 앞의 `알림:` 또는 `시스템:` 표기. 콜론과 세미콜론의 전각 문자도 허용
- `게임 시간: 12:34`, `남은 시간: 01:20`처럼 전체가 시계 값인 줄

예를 들어 `불꽃남자: 초코우유님이 게임을 떠났습니다`는 인용 채팅이라 유지합니다.
`[팀] 게임 시간: 12:34`, `게임 시간 (가렌): 12:34`도 채널이나 챔피언이 있는 채팅이라 유지합니다.

단, **채널·챔피언 없는 닉네임이 `게임 시간`이고 본문이 `12:34`인 경우**는 UI와 구분할 정보가 없어 제외합니다.
같은 조건에서 `알림`·`시스템`이라는 화자가 위 알림 전체를 인용한 경우도 구분할 수 없습니다.
이 기준과 알림 문구는 합성 입력으로 검증한 초기 규칙이며, 실제 게임의 시스템·핑 목록 확정은 **OPEN-09**로 남아 있습니다.

## 마일스톤 3: 정규화와 과잉 보정 방지

정규화 구현은 같은 모듈의 `normalization.py`에 있습니다. 기존 `impl.normalize(text)` 호출도 유지하며,
`run()`과 데이터 계약은 바꾸지 않습니다. `text`·`raw`·닉네임·챔피언은 정규화하지 않고 `text_norm`에만 결과를 넣습니다.

먼저 `http://`, `https://`, `www.`로 시작하는 URL과 ASCII 이메일 주소를 보호한 뒤, 나머지 구간에 아래 순서로 적용합니다.

| 순서 | 보정 범위 | 예시 | hints |
|---|---|---|---|
| 1 | 사전의 한글 변형·원형이 되는 글자 사이의 숫자·지정 특수문자 제거 | `시1발`, `시.발` → `시발` | `noise_removed` |
| 2 | 합쳤을 때 사전에 있는 자모열의 공백·탭 제거 | `ㅅ ㅂ` → `ㅅㅂ` | `jamo_joined` |
| 3 | `ㅋ`·`ㅎ`·`ㅠ`·`ㅜ`의 3회 이상 반복을 2회로 축약 | `ㅋㅋㅋㅋㅋ` → `ㅋㅋ` | `repeats_squeezed` |
| 4 | 사전의 한글 표현 사이에 끼인 `l`·`I`·`\|`·`o`·`O` 제거 | `시l발` → `시발` | `ocr_fixed` |
| 5 | 공유 사전의 변형·영타·초성을 원형으로 치환 | `TLQKF`, `ㅅㅂ` → `시발` | `lexicon:tlqkf`, `lexicon:ㅅㅂ` |

- 삽입 문자로 인식하는 특수문자는 `. ! * _ - · ㆍ …`와 너비 없는 공백(`U+200B`)입니다. 일반 공백이나 줄바꿈을 넘어 한글 단어를 합치지 않습니다.
- 사전 항목 앞뒤에 ASCII 영문·숫자·밑줄이 있으면 식별자로 보고 치환하지 않습니다. `mytlqkfbuild`, `tlqkf123`, `my시1발build`는 그대로입니다.
- 초성 사전 항목은 더 긴 자모열의 일부와 매칭하지 않습니다. `ㄱㅅㅂㅂ`, 사전에 없는 `ㄱ ㅅ ㅂ` 같은 열도 그대로입니다. 이미 완성된 초성 단어는 경계로 삼아 인접한 `ㅅ ㅂ`도 같은 실행에서 처리합니다.
- OCR 보정은 사전에 있는 한글 표현을 복원하는 데만 사용합니다. `LoL`, `l1`, `O0`, `미드2차`, `용 1분`, `12:34`, 일반 음절 반복과 문장부호는 일괄 변환하지 않습니다.
- `hints`는 실제 수행한 보정 순서로 기록하고 같은 항목은 한 번만 남깁니다. 영타의 대소문자는 같은 사전 키로 기록합니다.
- 사전과 컴파일된 규칙은 프로세스당 한 번 로딩합니다. CSV는 읽기만 하며, 시뮬레이터는 요청마다 새 worker를 실행하므로 다음 요청에 수정 사항이 반영됩니다.

지원하지 않는 신조어·임의 영타·모든 우회 조합을 추측해 복원하지는 않습니다. 실제 OCR 결과에서 발견한 변형을
익명화된 회귀 사례로 추가하고, 위 보호 규칙을 유지하면서 지원 범위를 넓힙니다.

## 검증 범위와 남은 작업

- `tests/test_parse.py`에서 기존 fixtures 일치, OCR 구분자 조합, 잘못된 헤더 제외, 증거 원문 보존, 알림 인용과 내 입력 보호를 검사합니다.
- 마일스톤 2에서 실제 시뮬레이터 HTTP→worker 경로로 기존 fixtures 10건과 OCR/UI 입력 3건의 반환값도 확인했습니다. 브라우저 화면이나 실제 게임 OCR 정확도를 검증한 것은 아닙니다.
- Windows에서 전체 테스트를 실행할 때는 기존 정책 테스트의 기본 인코딩 의존성 때문에 먼저 PowerShell에서 `$env:PYTHONUTF8 = "1"`을 설정합니다. 정책 테스트는 parse 담당 범위 밖이므로 수정하지 않습니다.
- 새 예시는 포지션이 드러나지 않는 가상 닉네임을 사용합니다(ADR-0020).
- 실제 게임 OCR 결과의 정확도·누락률 검증은 별도입니다. 사용자 설정 게임에서 얻은 자료를 익명화해 확인해야 합니다.
- 마일스톤 3은 단계별 기대값, 정상 문장·식별자·URL·이메일 보호, 세 가지 입력 출처의 원문 보존, 재실행 안정성을 검사합니다. 인접 표현 243개 조합도 다시 정규화할 때 결과가 달라지지 않는지 검증합니다.
- 마일스톤 3에서도 실제 시뮬레이터 HTTP→worker 경로로 기존 fixtures 10건과 복합 정규화·식별자 보호·`/all` 입력 등 4건을 추가 확인했습니다.
