- 브랜치는 `parse/<작업 내용>` 으로 만듭니다(예: `parse/first-try`). PR 에서 위 표의 범위 밖 파일을 바꾸면 CI `module-scope` 가 실패합니다(CONTRIBUTING.md).

## 마일스톤 2: OCR 헤더 대응

`source=ocr`와 `demo`의 줄에서 채널·화자·챔피언·본문을 분리합니다. 지원하는 헤더 구분자는 다음과 같습니다.

| 요소 | 허용 형식 | 예시 |
|---|---|---|
| 채널 | `팀`, `전체`. 대괄호·소괄호·전각 괄호와 괄호 안 가로 공백 | `[팀]`, `(팀)`, `[팀)`, `［ 팀 ］`, `（전체）` |
| 화자 | 공백이 있는 닉네임 허용. 헤더 구분자와 괄호가 닉네임에 섞이면 제외 | `불꽃 남자` |
| 챔피언 | 생략 가능. 소괄호·전각 소괄호 허용. 빈 괄호는 제외 | `(징크스)`, `（징크스）` |
| 본문 구분자 | 콜론·세미콜론과 각각의 전각 문자 | `:`, `;`, `：`, `；` |

- 채널을 읽지 못했지만 나머지 헤더가 정상이라면 `channel=unknown`입니다. 채널·화자·챔피언 문자를 추측해서 채우지 않습니다.
- 닫는 채널 괄호가 없거나 챔피언 괄호가 끊긴 줄은 잘못된 화자를 만들지 않고 `message=None`으로 돌려줍니다. 줄 합치기는 OCR 모듈의 책임입니다.
- `raw`는 원본 전체입니다. `text`는 본문 구분자와 직후의 공백 또는 탭 하나를 제외한 본문이며, 내부 기호·공백·후행 공백을 보존합니다. 헤더의 OCR 구분자 대응을 본문에 적용하지 않습니다.
- `source=self_input`은 헤더·시스템 판별을 거치지 않습니다. `/all` 명령 외에는 사용자가 쓴 문장을 본문으로 사용합니다.

## 시스템·UI 줄을 제외하는 기준

채널 표기가 없는 줄에서 아래 전체 형식을 검사합니다. 본문에 특정 단어가 있다는 이유만으로 채팅을 버리지 않습니다.

- `초코우유 (리신)님이 … 신호를 보냈습니다`, `초코우유님이 … 처치했습니다`
- `초코우유님이 게임을 종료했습니다`, `초코우유님이 게임을 떠났습니다`
- 위 알림 앞의 `알림:` 또는 `시스템:` 표기. 콜론과 세미콜론의 전각 문자도 허용
- `게임 시간: 12:34`, `남은 시간: 01:20`처럼 전체가 시계 값인 줄

예를 들어 `불꽃남자: 초코우유님이 게임을 떠났습니다`는 인용 채팅이라 유지합니다.
`[팀] 게임 시간: 12:34`, `게임 시간 (가렌): 12:34`도 채널이나 챔피언이 있는 채팅이라 유지합니다.

단, **채널·챔피언 없는 닉네임이 `게임 시간`이고 본문이 `12:34`인 경우**는 UI와 구분할 정보가 없어 제외합니다.
같은 조건에서 `알림`·`시스템`이라는 화자가 위 알림 전체를 인용한 경우도 구분할 수 없습니다.
이 기준과 알림 문구는 합성 입력으로 검증한 초기 규칙이며, 실제 게임의 시스템·핑 목록 확정은 **OPEN-09**로 남아 있습니다.

## 검증 범위와 남은 작업

- `tests/test_parse.py`에서 기존 fixtures 일치, OCR 구분자 조합, 잘못된 헤더 제외, 증거 원문 보존, 알림 인용과 내 입력 보호를 검사합니다.
- 마일스톤 2에서 실제 시뮬레이터 HTTP→worker 경로로 기존 fixtures 10건과 OCR/UI 입력 3건의 반환값도 확인했습니다. 브라우저 화면이나 실제 게임 OCR 정확도를 검증한 것은 아닙니다.
- Windows에서 전체 테스트를 실행할 때는 기존 정책 테스트의 기본 인코딩 의존성 때문에 먼저 PowerShell에서 `$env:PYTHONUTF8 = "1"`을 설정합니다. 정책 테스트는 parse 담당 범위 밖이므로 수정하지 않습니다.
- 새 예시는 포지션이 드러나지 않는 가상 닉네임을 사용합니다(ADR-0020).
- 실제 게임 OCR 결과의 정확도·누락률 검증은 별도입니다. 사용자 설정 게임에서 얻은 자료를 익명화해 확인해야 합니다.
- 정규화는 마일스톤 1의 공유 사전 치환과 `시1발` 같은 숫자 삽입 복원만 지원합니다. 자모 공백 결합·반복 축약·본문 OCR 보정·사전 치환 범위 보호는 **마일스톤 3**에서 구현합니다.
