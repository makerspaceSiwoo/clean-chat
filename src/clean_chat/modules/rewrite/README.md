# ④ rewrite — 선택된 게임 피드백을 담백한 한 문장으로

`run(RewriteRequest) -> Rewrite`는 L1 일 때, 그리고 L2 이상이고 `feedback_spans`가 있을 때 호출합니다.

- **L1 (대상 없는 욕설)**: 외부 호출 없이 욕설이 든 낱말을 통째로 지운 문장을 돌려줍니다. 예) `아 ㅅㅂ 내가 실수함` → `아 내가 실수함`. 욕설을 빼면 남는 말이 없으면 `rewritten=None` 이고, 정책표가 숨기거나(다른 유저) 복사할 내용 없음으로(내 채팅) 처리합니다. `**` 로 가린 글은 만들지 않습니다.
- **L2 이상 + 피드백**: 아래 설명대로 피드백만 팀원끼리 쓰는 담백한 말투로 다듬습니다. `~님`, `부탁드립니다` 같은 지나친 존댓말은 쓰지 않고, 원문이 반말이면 `~해 줘`, `~하자` 처럼 부드러운 반말로 둡니다.
예: `야 정글 ㅂㅅ아 용 먼저 치라고` + `용 먼저 치라고` → `용 먼저 치자`.
원문/분석은 수정하지 않습니다. `RewriteRequest.players`는 기본값이 빈 목록인 경기 명단이며 기존 입력과 호환됩니다.

## 설정과 실행

```bash
uv sync --extra rewrite
uv run sim rewrite
uv run pytest tests/test_rewrite.py -q
```

로컬 `.env`에 `LLM_BACKEND=api`, `GEMINI_API_KEY=<키>`를 설정합니다. 모델은 기본값 `gemini/gemini-3.1-flash-lite`(`backend.DEFAULT_MODEL`)를 쓰고, `LLM_MODEL=gemini/<모델명>`을 설정하면 그 값이 우선합니다.
`LLM_API_KEY`도 지원하며, 설정이 없거나 호출 실패/거절/시간 초과면 예비 규칙 또는 `rewritten=None`입니다.
키·원문 로그·실행 결과 CSV는 커밋하지 않습니다. `LLM_BACKEND=rule`은 API 없이 제한된 예비 규칙만 씁니다.

## 입력과 생성

- `feedback_spans`는 analyze가 원문에서 선택한 게임 피드백입니다. 시뮬레이터에서는 `/`로 구분합니다.
- 출처 확인은 원문 부분 문자열을 기본으로 하며 띄어쓰기·기호와 `쳐먹→먹` 정리 차이도 허용합니다.
- 요청마다 `NicknameCodec`가 경기 명단의 닉네임을 고유한 `플레이어_랜덤4자리`로 치환합니다. 영문 대소문자 차이도 처리하고 챔피언명은 그대로 둡니다.
- API에는 같은 대응표로 치환한 `original`, 분석된 욕설 조각을 지운 `cleaned`, `feedback_spans`를 함께 보냅니다.
  명단 자체/raw/화자 메타데이터와 대응표는 전송하지 않습니다. 원문은 문맥 참고용이며 선택되지 않은 지시를 결과에 추가하면 안 됩니다.
- 모델은 욕설·비난 없는 담백한 문장과 의미 확인 5항목을 한 응답으로 반환합니다. 별도 검증 API나 자동 재시도는 없습니다.
- SDK는 첫 생성 호출 때 `functools.cache`로 한 번 준비합니다. 모듈 import만으로 SDK/프로세스/서버를 시작하지 않습니다.
- 실제 앱에서는 같은 프로세스에서 호출합니다. 시뮬레이터는 공용 실행 방식대로 매번 새 프로세스를 사용하므로
  초기 SDK 준비 시간이 더해질 수 있습니다. 모듈 안에서 별도 HTTP 서버나 자식 프로세스를 띄우지 않습니다.

## 출력 검사와 대체 처리

공용 `data/lexicon/bypass.csv`와 명백한 비속어 보완 목록, 분석된 욕설 조각을 검사합니다.
`죽어도 괜찮으니`, `라인 못하겠으면` 같은 문장은 해당 단어만으로 막지 않고 명확한 비난 패턴을 구분합니다.
코드 치환·검사·복원은 Gemini 호출과 분리된 요청 단위 클래스가 담당합니다. 모델 출력에서 선택된 코드가 누락/변형되거나 다른 코드가 추가되면 예비 규칙을 사용합니다. 검증된 결과만 원래 닉네임으로 복원해 반환합니다.
대상·행동·질문/금지·수치·순서·조건·고유명사·종류를 보존해야 합니다. 수치의 추가뿐 아니라 누락/변경도 막고, 닉네임 코드의 숫자는 수치 검사에서 제외합니다. `용→드래곤`은 가능하지만
원문에 없는 바다용/화공용을 지어내면 거절합니다. 로컬 대상·챔피언 검사는 선택된 피드백의 대상이 빠지면 거절하고, 피드백 밖이라도 **원문 문장에 있던** 포지션·챔피언을 호칭으로 붙이는 것은 허용합니다 (`정글 멍청아 와드 좀 박아` → `정글 와드 좀 박아 줘` 통과, `미드 와드 좀 박아 줘` 거절).
말투 검사는 존댓말, 부드러운 반말 요청(`~줘`, `~하자`, `~지 마`), 질문형을 받고 `~라`, `~라고`, `~냐` 로 끝나는 명령·추궁은 거절합니다.
피드백 조각에 욕설·비하어(`쓰레기`, `멍청` 등)가 섞여 오면 Gemini 가 빼고 다듬은 결과만 씁니다. 다듬지 못하면 조각을 그대로 보이지 않고 `None`(숨김)입니다.
기존 fixture의 `왜 안 와`처럼 대상이 생략된 합류 요청만 원문에 있는 단일 포지션을 보완합니다.

API 의미 확인과 로컬 검사를 통과해야 반환합니다. 거절된 결과도 안전한 예비 규칙을 시도하며,
예비 규칙 결과에도 같은 로컬 검사를 적용합니다. 모호한 문장은 None일 수 있고 의미 확인은 완전한 보장이 아닙니다.
SDK 준비와 응답 대기까지 포함해 run()의 3초 예산을 지키며, 늦은 결과는 버립니다.
준비만으로 예산이 소진되면 뒤늦은 API 호출을 시작하지 않습니다.

동일한 문맥/피드백/모델·키/검사 조건의 검증된 성공 결과만 프로세스 메모리에 120초, 최대 128개 재사용합니다.
실패는 저장하지 않으며 캐시 적중 시에도 현재 요청의 새 코드로 다시 치환해 로컬 검사를 합니다. 새 요청의 msg_id를 유지하고 파일에 저장하지 않습니다.

## 디버깅

입력 검사 → 모델/키 설정 여부 → 실제 프롬프트/입력 → 응답 시간·토큰 → 의미 확인 → 로컬 검사 → 예비 규칙/최종 사유를 표시합니다.
키·알려진 닉네임은 마스킹합니다. 원문 본문이 디버그 로그에 포함될 수 있으므로 로컬에서만 확인합니다.
캐시 재사용은 API 호출 없음/추가 0토큰으로 표시합니다.
