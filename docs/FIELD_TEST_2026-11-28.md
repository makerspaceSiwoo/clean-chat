### 사용 순서 (바뀐 점)
1. 처음 실행하면 **준비 화면**: Gemini API 키 입력(필수) + 분석 모델 자동 다운로드(약 440MB).
2. 홈에서 **오버레이 실행** → 채팅창 위에 맞춤 → **위치 잠금**. 잠근 순간부터 게임으로 보고 읽습니다.
3. 게임이 끝나면 **오버레이 종료**. 이때 신고 메시지·고소장 초안과 **채팅 기록** 화면이 채워집니다.
4. 앱은 게임 창을 찾지 않습니다. 오버레이가 가린 사각형만 1초마다 캡처합니다. 자동 종료도 없습니다.

### 3-3. 합성 영상 점검 (실제 게임 없이)

롤 채팅을 흉내 낸 500×300 영상(54초, 채팅 68줄 + 시스템 문구 8줄, 정답표 포함)을 1초 간격 프레임으로 잘라 앱과 같은 흐름(실제 OCR → … → report)으로 돌렸다. 명단은 비움.

| 단계 | 처리된 채팅 | 등급 일치 | 고소장 |
|---|---|---|---|
| 수정 전 | 29 / 68 | 29 / 29 | 없음 (L3 두 줄 모두 놓침) |
| 수정 후 | 68 / 68 | 67 / 68 | 돌여울 1건, 증거 2줄 |

- **시간이 닉네임에 붙은 줄** (`[00:12]물비늘(쓰레쉬):…`): parse 가 채팅으로 보지 않았다 → 대괄호 시간은 붙어 있어도 읽는다.
- **팀 채팅 머리의 콜론 빠짐** (`[13:18]돌여울(가렌)정글…`): OCR 머리 복구가 `[전체]`·`[팀]` 줄에만 적용됐다 → 시간으로 시작하는 줄도 복구 (`(챔피언)님이` 알림은 제외).
- **HUD 가 겹쳐 깨진 머리** (`-[06:0거돌여울아렌):…`, `(` 빠짐): 이번 게임에서 이미 본 사람(또는 명단)과 "닉네임+챔피언" 유사도 0.75 이상, 2등과 0.1 이상 차이날 때만 복구 (`core/pipeline.py: SpeakerBook.repair_head`). 복구한 말이 최근에 처리한 말과 같으면 버린다(중복 증거 방지). `capture.log` 에 "머리 복구" 로 남는다.
  - 넣기 전 확인: 실측 게임 기록(961줄)에서는 복구가 한 번도 일어나지 않았다(`):` 가 있는 실패 18줄은 모두 내용이 빈 화자 조각). 즉 정상 줄을 건드리지 않는다.
  - 한계: 처음 말하는 사람은 복구하지 못한다. 닉네임+챔피언이 비슷한 사람이 둘이면 복구하지 않는다.
- rewrite: 비난(`뭐하냐`)이 섞인 피드백 조각은 Gemini 가 다듬지 못하면 숨긴다 (Gemini 첫 호출이 3초를 넘겨 그대로 보였음).
- 남은 오답: `아 ㅅㅂ …` 를 OCR 이 `아ㅅ브` 로 읽어 L0. 띄어쓰기를 빠뜨린 OCR 결과에서 L1 욕설 낱말을 지우면 붙은 말까지 지워진다.
- 정답표의 화자 기대값은 L1 만 한 사람(달솜·밤도토리)도 "신고" 로 적혀 있다. 앱 정책은 L1 을 신고하지 않는다 — 정답표 기준 확인 필요.

## 5. 사용자 확인 없이 기본값으로 정한 것

- **게임 자동 종료 없음.** "게임 창 판별 없이"라는 요청에 따라, 게임 창이 사라져도 종료하지 않습니다. 오버레이 종료를 눌러야 합니다.
- **L1 은 Gemini 를 부르지 않고 로컬에서 욕설 낱말만 지움.** 문장을 다시 쓰지는 않습니다.
- **필터 강도 "낮음"(L1 원문 표시)·"높음"(L1 숨김)은 그대로.**
- **앱이 받는 모델은 실시간 분류 모델 하나.** 대화 판단(judge) 모델은 앱이 쓰지 않아 받지 않습니다.
- **포지션 비하어만 있고 비난이 없으면 L1**(신고 안 함), 비난과 함께면 L2.
- **`죽인다` 는 문맥으로 구분합니다.** 게임 낱말·콜(`ㄱㄱ`, `가자`)이 있으면 L0, 문장만 보면 L2(비난)입니다. 현실 표지(`실제로`, `집 앞`, `겜 끝나면` …)가 있거나, 같은 화자가 15분 안에 누군가를 공격하던 중이면 협박 L3 입니다. 앱은 judge 를 부르지 않아서, 실시간 analyze 가 앞 대화 10줄로 judge 와 같은 기준을 씁니다 (시뮬레이터 점검 후 수정).
- **rewrite 의 "불확실하면 버린다" 원칙 완화.** 다듬지 못한 피드백을 원문 조각 그대로 보여 줍니다. 단, 조각에 욕설·비하어(`쓰레기` 등)가 섞였으면 그대로 보이지 않고 숨깁니다 (시뮬레이터 점검 후 수정).
- **rewrite 말투는 "적당히".** 사용자 요청으로 `~님, 부탁드립니다` 대신 팀원끼리 쓰는 담백한 말투(`정글 와드 좀 박아 줘`)로 바꿨습니다. 원문 문장에 있던 포지션·챔피언은 호칭으로 붙일 수 있습니다.

## 6. 주의

- **앱은 한 번에 하나만 실행하세요.** 확인할 때는 실행 전에 기존 프로세스가 없는지 보고, 실행 뒤 프로세스 수를 확인합니다. 1번 문제가 다시 생기면 창이 2초마다 하나씩 늘어납니다.
- **빌드는 실행 중인 앱의 폴더(`dist/`)를 덮어씁니다.** 앱을 종료한 뒤 빌드하거나, `build_desktop.build(다른 폴더)` 로 따로 만드세요. 판독 중인 앱을 종료하면 그 판의 기록이 사라집니다.
- **모듈 범위.** 이 브랜치는 리드 지시로 `modules/ocr`, `parse`, `analyze`, `rewrite`, `report` 를 직접 고쳤습니다. `feat/`·`fix/` 브랜치는 `module-scope` 검사를 건너뛰어 CI 에서는 통과로 보입니다. 각 담당자에게 알려야 합니다.
- **계약 변경.** `core/schemas.py` SCHEMA_VERSION 2.2.0: `Frame.image`(직렬화 제외), `ReportRequest.champion`, `ReportDraft.champion`. 모두 기본값이 있어 기존 예시는 그대로 통과합니다.
- **실제 닉네임.** 이 브랜치의 앞쪽 커밋(테스트 파일과 커밋 메시지)에 실측에 쓴 계정의 닉네임이 들어 있습니다. 파일에서는 예시 이름으로 바꿨지만 커밋 기록에는 남아 있습니다. squash merge 하면 main 기록에는 남지 않습니다.
